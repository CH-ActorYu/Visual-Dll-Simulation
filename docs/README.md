## 文档职责

- 需求或范围变化先修改 `01`；
- 公共类型、签名或依赖变化同步修改 `02` 和 `05`；
- 检测、标定、公式或算法假设变化修改 `04`；
- 验证口径或样本变化修改 `06`；
- 任务完成后更新 `03` 的状态表，并与对应代码放在同一提交；
- 过程问题写入 `ISSUE`，解决后补充原因、方案和提交号。

发生冲突时，需求范围以 `01` 为准，公共 API 以 `02` 和 `05` 的一致版本为准，算法细节以 `04` 为准，验收口径以 `06` 为准。
