## 1. 测试层级

| 层级 | 目标 | 是否依赖设备/SDK |
| --- | --- | --- |
| 单元测试 | 值对象、配置、公式、候选选择、状态和所有权规则 | 否，使用 mock |
| 架构测试 | 分层引用、SDK 类型隔离、UI 隔离、public API 边界 | 否 |
| 引擎适配测试 | OpenCV 转换、算法、文件帧源和异常转换 | OpenCV runtime；默认不依赖相机 |
| 集成测试 | 视频 → 检测 → 标定 → 测距结果闭环 | OpenCV + 固定测试数据 |
| 设备测试 | 枚举、参数、断开、重连和幂等停止 | 指定 USB 相机 |
| 验收测试 | S1~S8、宿主集成、性能和稳定性 | 完整环境 |

## 2. 测试数据管理

仓库建立 `test-assets/` 或独立受控测试数据包，至少包含：

- 单目标、空 ROI、多个候选、目标触边、部分遮挡、亮/暗前景图片；
- 固定分辨率的短视频和 10 分钟性能视频；
- 近、中、远三个已知距离的数据；
- 错误格式、损坏视频和空图片目录；
- 每个样本的预期目标框、像素宽度、状态及允许误差；
- 数据来源、许可证、拍摄设备、分辨率和标定信息。

大型二进制数据不直接无说明地提交；需记录获取方式、校验哈希和许可证。测试不得依赖开发者机器上的任意绝对路径。

## 3. 输入契约测试

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| IN-01 | 一个合法 TargetRegion | 返回一条相同 TargetId 的结果 |
| IN-02 | 多个合法 TargetRegion | 结果数量、顺序和 TargetId 与输入一致 |
| IN-03 | TargetId 重复 | `VisionException(InvalidInput)` |
| IN-04 | 空 TargetId / 空 Targets | `VisionException(InvalidInput)` |
| IN-05 | ROI 部分越界 | 按统一规则收敛后处理 |
| IN-06 | ROI 完全越界 | `VisionException(InvalidInput)` |
| IN-07 | ROI 小于最小尺寸 | 返回明确无效输入，不伪装为未检出 |
| IN-08 | 帧格式/Stride/尺寸不合法 | `VisionException(InvalidInput)` |
| IN-09 | 处理中修改宿主配置 | 当前帧使用旧快照，下一帧完整使用新快照 |

## 4. 目标检测测试

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| DET-01 | ROI 中一个合法目标 | 框、中心、像素尺寸在标注容差内 |
| DET-02 | 空 ROI | NotDetected |
| DET-03 | 小噪点 | 被面积过滤，不误检 |
| DET-04 | 两个合法候选、无历史 | 选择面积较大者 |
| DET-05 | 两个合法候选、有历史 | 选择与历史中心更接近者 |
| DET-06 | 目标接触 ROI 边界 | 降低置信度或 NotDetected，不输出错误尺寸 |
| DET-07 | 跟踪失败 | 立即重新检测 |
| DET-08 | 达到 RedetectInterval | 强制重新检测并更新跟踪状态 |
| DET-09 | 明暗前景切换 | 按 ForegroundPolarity 得到正确候选 |
| DET-10 | 测量轴不同 | TargetPixelSize 始终与配置轴一致 |

检测位置建议容差不超过 2 px；最终容差必须随固定测试数据一起记录。

## 5. 标定与距离测试

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| CAL-01 | W、P0、Z0 合法 | 正确生成 F |
| CAL-02 | 任一关键参数 <= 0 | InvalidInput，旧标定保持有效 |
| CAL-03 | 10~30 帧中含异常宽度 | 中位数不被单个异常值显著影响 |
| CAL-04 | 相机 ID 改变 | 标定失效 |
| CAL-05 | 分辨率/焦距/Profile/MeasureAxis 改变 | 标定失效 |
| CAL-06 | 新标定验证失败 | 不覆盖旧标定 |
| DST-01 | P=P0 | Z=Z0 |
| DST-02 | P=P0/2 | Z=2×Z0 |
| DST-03 | P=2×P0 | Z=Z0/2 |
| DST-04 | P<=0 | Failed/InvalidInput，不除零 |
| DST-05 | 未标定单帧调用 | 抛 NotCalibratedException |
| DST-06 | 未标定实时流 | 输出 NotCalibrated，流保持可恢复 |
| DST-07 | 近/中/远各 10 次 | 平均绝对百分比误差 <= 10% |

距离误差计算：

```text
绝对百分比误差 = abs(测量值 - 真实值) / 真实值 × 100%
```

验收报告同时记录平均值、最大值、标准差和有效样本数，不能只报平均值。

## 6. 帧生命周期测试

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| LIFE-01 | 单帧 MeasureAsync 正常完成 | 模块不释放调用方租约，返回后无帧引用 |
| LIFE-02 | MeasureAsync 取消 | 调用方租约仍归调用方，模块内部临时资源已释放 |
| LIFE-03 | FrameBuffer 写入成功 | 所有权转移，调用方不再释放 |
| LIFE-04 | FrameBuffer 写入失败 | 所有权仍归调用方 |
| LIFE-05 | 缓冲满 | 最旧租约释放，DroppedCount 增加 |
| LIFE-06 | ReadLatest | 更旧未消费租约全部释放 |
| LIFE-07 | Complete/Stop/Close 重复调用 | 幂等，无双重释放异常 |
| LIFE-08 | SDK 转换抛异常 | Mat/转换租约/源租约按所有权规则释放 |
| LIFE-09 | 设备断开 | 当前帧和队列租约释放，状态明确 |
| LIFE-10 | UI 消费缓慢 | 队列不增长，采集线程不被 UI 阻塞 |

测试使用可计数的 fake memory owner，断言租用数最终等于归还数，并检测释放后访问。

## 7. 配置与错误测试

- 配置 schema 版本不支持；
- JSON 字段非法并能定位字段；
- 配置失败后旧配置完整保留；
- SetCalibration 原子替换；
- SDK 异常转换为 VisionException；
- EngineUnavailable、LicenseInvalid、NotSupported、DeviceLost 状态正确；
- 一个可选引擎不可用不影响其他引擎发现和启动。

## 8. 性能基线

正式验收前固定并记录：

- CPU、内存、操作系统、.NET SDK/runtime 版本；
- OpenCV 与 runtime 版本；
- 图像分辨率和像素格式；
- ROI 数量和尺寸；
- 使用的检测 Profile；
- 视频文件及校验哈希；
- Debug/Release、是否附加调试器；
- 预热时间和统计时间。

构建和验收只使用 `global.json` 固定的正式 .NET 10 SDK；RC/Preview SDK 结果不得作为正式验收结论。

建议口径：

- Release x64、无调试器；
- 预热 30 秒后统计；
- 720p、单 ROI、默认检测 Profile；
- 连续 10 分钟吞吐 >= 15 帧/秒；
- 单帧处理报告平均值、P95、P99，不只报告最小值；
- 停止/取消目标上限在实现前明确，建议正常情况下 <= 2 秒；
- 复制次数、DroppedCount 和端到端延迟同时记录。

## 9. 稳定性与内存

2 小时测试分阶段记录：启动后、预热后、每 10 分钟和结束时。

分别记录：

- 托管堆；
- Working Set / Private Bytes；
- OpenCV 原生内存；
- 池已租用/已归还/峰值；
- 当前和峰值队列长度；
- DroppedCount；
- 处理成功、未检出和失败帧数。

“内存增长 <10%”以预热完成后的稳定基线为起点；同时检查曲线不存在持续单调增长。只看结束点百分比不足以证明无泄漏。

## 10. S1~S8 验收记录

每个场景记录：

| 字段 | 内容 |
| --- | --- |
| 场景编号 | S1~S8 |
| 日期/执行人 | 实际信息 |
| 代码提交 | 完整 commit id |
| 环境 | OS、SDK、runtime、CPU、内存、相机、引擎版本 |
| 数据 | 文件名、哈希、标定信息 |
| 步骤 | 实际执行步骤 |
| 结果 | 数值、日志、截图或报告路径 |
| 结论 | Pass / Fail / Blocked |
| ISSUE | 失败或阻塞对应编号 |

S4 必须在全新控制台项目中仅引用分发 DLL 组验证；S5 必须由 HardwareModularWorkflow 的真实集成路径验证，不能用 Visual.App 内部调用代替。

## 11. CI 与人工测试边界

每次提交必须执行：

- 编译；
- 单元测试；
- 架构测试；
- 不依赖设备的 OpenCV 样本测试；
- Markdown 链接与格式检查。

相机、许可证、2 小时稳定性和宿主集成可在专用环境人工或计划任务执行，但结果必须归档并关联提交号。
