# 目标登记、跟踪与侧栏预览

## 1. 目标

软件先由用户提供一个明确物品，之后在连续视频中寻找同一个物品、跟踪其位置，并根据当前目标像素尺寸计算距离。

目标登记支持两种入口：

1. 提供目标样本（导入参考图，或把实际物品放入相机画面后拍摄样本）；
2. 在实际视频的某一帧中圈选目标内容。

两种入口必须生成同一种运行时目标定义，后续跟踪、丢失重找、测距和 UI 展示不得按来源分成两套流程。

## 2. 概念边界

| 概念 | 含义 | 不是 |
| --- | --- | --- |
| 目标定义 | 用户要求系统持续寻找的具体物品，包含稳定 `TargetId`、参考外观、轮廓和测量轴 | 临时鼠标矩形 |
| 选择区域 | 用户在参考图或视频帧中给出的粗略范围，可为套索/多边形 | 算法确认的最终物体边缘 |
| 目标轮廓 | 算法从选择区域中分割出的实际不规则边缘 | 外接矩形 |
| 搜索范围 | 跟踪或重找时缩小计算区域的矩形边界 | 目标身份 |
| 目标预览 | UI 依据当前帧和目标轮廓生成的透明背景裁图 | 公共测距结果中的完整图像副本 |

必须保留矩形 `Bounds` 作为快速裁剪、搜索和兼容字段，但不得再把 `Bounds` 当作目标真实形状。

## 3. 用户流程

### 3.1 提供目标样本

1. 用户导入目标图片，或将实际物品放入相机画面并拍摄一帧作为样本；
2. 软件自动分割主体，必要时允许用户用套索修正范围；
3. 右侧“目标”面板显示透明背景的主体预览；
4. 用户确认目标，并填写测距所需的真实尺寸/测量轴；
5. 视频启动后进入寻找与跟踪。

### 3.2 从实际视频选择

1. 视频正常显示，用户点击“选择目标”；
2. UI 冻结一张选择帧，但采集线程不能被阻塞；
3. 用户用套索圈定目标，算法在套索内分割真实轮廓；
4. 右侧显示目标预览，用户确认后建立目标定义；
5. UI 恢复实时显示并开始跟踪。

### 3.3 运行状态

目标状态使用明确状态机：

`未登记 → 登记中 → 已就绪 → 跟踪中 → 暂时丢失 → 重找中 → 跟踪中/未找到`。

丢失后不能继续显示旧距离。右侧可以保留最后一次目标图像用于对照，但必须变暗并标记“目标丢失”，不得伪装成当前帧结果。

## 4. UI 布局

视频区只承担源画面和选择交互：

- 选择过程中显示套索线；
- 运行时不在视频内部放置“ROI 已选定”标签或目标裁图；
- 如需定位反馈，仅显示可关闭的细轮廓/中心标记，不覆盖目标内容。

右侧新增“目标”卡片：

- 当前目标透明裁图，棋盘格表示透明背景；
- `目标名称/TargetId`；
- 跟踪状态与置信度；
- 当前像素尺寸、测量轴和距离；
- “导入目标”“从视频选择”“重新登记”“清除目标”操作。

参考目标与当前跟踪目标需要同时对照时，显示为“参考”小图和“当前”主图，不得覆盖在视频画面中。

## 5. 契约调整

### 5.1 Vision.Contracts

增加引擎无关的紧凑几何类型：

- `TargetSelection`：选择多边形及其矩形边界；
- `TargetShape`：算法确认的轮廓点、边界、中心和测量轴尺寸；
- `ITargetModel`/目标模型句柄：运行期目标外观模型，带 `EngineId` 和释放语义，不暴露 OpenCV 类型；
- `ITargetModelFactory`：从参考帧和选择区域建立运行期目标模型；
- 跟踪结果返回 `TargetShape`、置信度和跟踪状态。

公共契约传递经过简化的轮廓点，不逐帧传递整幅二值 Mask。Mask 属于引擎内部临时资源，避免破坏帧租约和造成大图复制。

### 5.2 Distance.Contracts

目标登记属于带真实尺寸和测量语义的业务状态，应由 Distance 层持有：

- `TargetDefinition`：`TargetId`、参考资源标识、真实尺寸、测量轴、引擎/配置版本；
- `DistanceRequest` 引用已登记目标和可选搜索范围；
- `DistanceMeasurement` 增加可选 `TargetShape` 与跟踪状态，保留原有 `TargetBounds` 兼容字段；
- 未登记、目标丢失、重找中必须返回不同的明确状态，不能都折叠成 `NotDetected`。

参考图片和预览图片不直接嵌入配置 JSON。配置保存资源路径、内容哈希和版本；运行时重新建立引擎目标模型。

## 6. OpenCV 实现

### 6.1 登记

1. 将用户套索转换为 ROI 内 Mask；
2. 灰度、滤波、阈值和形态学处理；
3. 在 Mask 内选择最可信轮廓；
4. 使用 `ApproxPolyDP` 简化轮廓，避免保存大量点；
5. 保存透明目标裁图、轮廓、灰度模板和必要的特征描述。

### 6.2 跟踪与重找

- 跟踪器预测下一帧局部搜索范围；
- 在局部范围重新分割轮廓，更新真实像素尺寸，不能长期沿用固定模板宽度；
- 模板匹配应使用目标 Mask；需要旋转/尺度鲁棒性时增加 ORB 特征匹配；
- 置信度低于阈值或连续丢失时转入扩大范围重找；
- 重找成功后更新跟踪器，但不得静默换成外观不相符的其他物体。

测距使用当前帧轮廓的旋转最小外接矩形或约定方向投影尺寸，并与标定时的测量轴保持一致。仅使用固定外接矩形宽度会在目标缩放或旋转时产生错误距离。

## 7. 帧与 UI 交接

必须先解决 `I-005`，再增加目标预览：

- 采集、目标识别和测距在后台流水线执行；
- UI 仅接收不可变的“最新结果快照”，不得消费逐帧积压队列；
- 视频和目标侧栏分别节流，建议不超过 15 FPS 和 10 FPS；
- 目标预览只复制轮廓外接范围，并复用 `WriteableBitmap`；
- UI 快照创建必须在原帧租约释放前完成，之后不得持有 `ImageFrame` 或原生 SDK 对象；
- 停止、关闭和切换目标均设置超时，并释放跟踪模型与预览缓冲。

## 9. 当前不采用的方案

- 不把用户手绘套索直接当成永久目标轮廓；手绘只是粗约束；
- 不删除矩形边界；它仍用于快速搜索和兼容；
- 不让 WPF 直接调用 OpenCV 生成 Mask；
- 不在 `DistanceMeasurement` 中逐帧携带目标图片或完整 Mask；
- 不在修复 UI 卡死之前增加第二路逐帧图片刷新。
