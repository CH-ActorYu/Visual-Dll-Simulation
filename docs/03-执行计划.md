## 0. 给接手者的 30 秒摘要

- **做什么**：视觉功能组件库 Visual + WPF 桌面端。本期只做**测距模块**（圈选目标 → 标定 → 实时输出 mm）。
- **当前状态**：M0~M4 已完成；OpenCV runtime、P0 图像算子、Blob 检测、基础跟踪、图像适配及三类帧源均已落地。下一任务从 M5 开始。
- **最重要的一条**：业务模块和共享契约不引用任何具体视觉引擎；OpenCV/HALCON/VisionPro 只能通过独立适配器接入。
- **做完一个任务**：当场更新本文档 §7 任务状态表（状态 + 完成日期 + 提交号）再提交代码，方便下个会话接着干。

## 3. 编码约定

- 所有工程：`<Nullable>enable</Nullable>`、`<ImplicitUsings>enable</ImplicitUsings>`、`<LangVersion>latest</LangVersion>`；
- 公共 API：异步方法 `Async` 后缀，带 `CancellationToken ct = default`；
- 目录即命名空间：`Contracts/` 放对外类型（public），`Internal/` 放实现（internal）；
- `InternalsVisibleTo` 仅授予对应 `*.Tests` 工程；
- 提交信息：`feat/fix/docs/test: 简述`（参考 git log 风格）。

## 6. 新会话接手流程（AI/人都一样）

1. 读本文档 §0~§1，再读 02 文档对应模块章节；
2. `git log --oneline -5` 看最近进展；查 §7 状态表找第一个 `⬜ 待开始` 任务；扫一眼 [ISSUE](./ISSUE.md) 中 `🔴/🔨` 状态的问题；
3. `dotnet test` 确认当前全绿（不绿先修，不急着做新任务）；
4. 开发 → 测试 → **先把完成结果反馈到 §7 状态表**（状态、日期、提交号、遗留问题）→ 再提交代码（信息含任务号，如 `feat: M2.3 VideoFileSource`）；状态表与代码必须在同一提交内更新，不允许"代码做完了表没改"；
5. 过程中遇到的问题按格式记入 [ISSUE](./ISSUE.md)，解决后补原因、方案与提交号。
