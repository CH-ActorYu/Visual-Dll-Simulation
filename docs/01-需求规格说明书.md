## 1. 产品定位

本项目是一款视觉相关的桌面软件。核心诉求：

> **每项业务功能都是一个独立模块（独立 DLL / 独立项目），可以从软件中单独拆出来，给到别的项目直接引用使用。**

两个关键概念（判定细则见 §4.6）：

- **业务功能**：输出带业务结论的完整场景（如"测距"输出 mm），单独成模块 DLL；
- **基础能力**：采集、预处理、找目标、跟踪等通用能力，不单独成业务模块；契约和公共流程沉淀在共享层（Abstractions / Image / IO / Vision.Contracts / VisionBase），具体 SDK 实现位于引擎适配器，被各业务模块通过接口复用。

因此交付物分两层：

| 层 | 交付物 | 使用者 |
| --- | --- | --- |
| 软件层 | `Visual.App`（WPF 可执行程序）：完整的操作界面，加载各功能模块 | 直接操作软件的人 |
| 模块层 | `Visual.<功能>.dll`（如 `Visual.Distance.dll`）：纯算法/业务类库，**不依赖 UI**，可被任意 .NET 项目引用 | 其他软件项目（首个消费者：HardwareModularWorkflow 硬件工作流平台） |

典型消费场景：HardwareModularWorkflow 引用测距 DLL 组，在其 `OpenCvCameraDriver`（`IHardwareDriver` 实现）内调用测距 API，把"实时测距"变成工作流中的一个硬件步骤——**模块 DLL 是被调用方，不感知宿主的存在**。

```
┌─────────────────────────────┐   ┌──────────────────────────────────┐
│ Visual.App (WPF 软件)        │   │ HardwareModularWorkflow          │
│  └─ 引用 → Visual.Distance  │   │  └─ OpenCvCameraDriver           │
│            .dll 组           │   │       └─ 引用 → 测距 DLL 组       │
└─────────────────────────────┘   └──────────────────────────────────┘
              同一组 DLL，两种消费方式
```

## 2. 目标（Goals）

| 编号 | 目标 | 说明 |
| --- | --- | --- |
| G-01 | 功能可用 | 软件内完成"视频输入 → 圈选目标 → 标定 → 实时距离输出"闭环 |
| G-02 | 模块可拆 | 功能模块编译为独立 DLL，拷贝/引用到外部项目即可用，无需携带 WPF 软件 |
| G-03 | API 稳定 | 模块对外只暴露接口 + DTO，内部算法可换、版本演进不破坏调用方 |
| G-04 | UI 可换 | 软件界面只是模块的一种宿主；模块不引用任何 UI 框架 |
| G-05 | 功能可扩 | 后续新增业务功能 = 新增一个模块项目 + 软件内挂载，不改已有模块与共享层 |

## 3. 需求约束（Constraints）

### 3.1 模块 DLL 约束（可拆性的根本保障）

| 编号 | 约束 |
| --- | --- |
| C-01 | 模块项目为纯类库（`net10.0`），**禁止引用 WPF/WinForms/任何 UI 框架** |
| C-02 | 业务模块对外只暴露接口（如 `IDistanceService`）+ DTO（如 `DistanceMeasurement`）+ 工厂/构建入口；实现类 `internal`；共享层的通用契约类型按其公共用途公开 |
| C-03 | 业务模块只能依赖共享契约、图像抽象和视觉能力接口；不得直接依赖 OpenCV、HALCON、VisionPro 或其他具体引擎 |
| C-04 | 模块不读写调用方的文件/配置系统；所需参数（标定值、阈值）全部由调用方经 API 传入，序列化格式（JSON）由模块定义 |
| C-05 | 公共业务、IO、设备生命周期和实时流 API 提供异步形式并接受 `CancellationToken`；无 IO 的单帧 CPU 算子可同步，但只能由后台处理线程调用，不得阻塞 UI 或采集线程 |
| C-06 | 模块抛出的异常收敛为模块自定义异常类型，不向调用方泄漏内部第三方异常 |
| C-07 | 模块带语义化版本号（如 `Visual.Distance 1.0.0`），公共 API 变更遵循 SemVer |
| C-08 | 每个模块配套**无 UI 的测试工程**（xUnit 控制台可跑），证明脱离软件可用 |

### 3.2 软件层约束

| 编号 | 约束 |
| --- | --- |
| C-09 | 软件分层：App（WPF UI）→ AppCore（交互/编排）→ 业务模块；业务模块通过视觉能力接口使用共享层和引擎适配器，UI 不直接写算法 |
| C-10 | 技术栈：.NET 10 / WPF / CommunityToolkit.Mvvm；首个视觉引擎为 OpenCV，HALCON/VisionPro 通过独立适配器接入；DI 用 Microsoft.Extensions.DependencyInjection |
| C-11 | 软件通过项目引用或模块目录加载业务模块；业务模块和引擎适配器同时以 DLL 形式构建输出 |
| C-12 | 耗时操作全部异步，UI 线程不阻塞 |

### 3.3 范围约束（本期）

| 编号 | 约束 |
| --- | --- |
| C-13 | 本期业务功能仅**实时目标测距**一个模块；软件壳（视频源、圈选、叠加显示）为配套 |
| C-14 | 本期实现为单相机、单 ROI、单目标，但 **API/DTO 按多目标、多帧源兼容设计**（见 §5.5-A）；测距方案为单目 + 标定 |
| C-15 | 后续新业务功能（若有明确消费者）按同一模块规范追加，不在本期实现 |

### 3.4 视觉引擎与厂商 SDK 约束

| 编号 | 约束 |
| --- | --- |
| C-16 | `Visual.Abstractions`、`Visual.Image`、`Visual.Vision.Contracts` 不得引用 `Mat`、HALCON `HObject`、VisionPro `CogImage` 等具体引擎类型 |
| C-17 | OpenCV、HALCON、VisionPro 必须分别放在独立适配器工程；厂商 SDK 类型不得穿透适配器边界进入业务模块 |
| C-18 | 引擎适配器负责图像格式转换、采集、预处理、检测、跟踪和原生异常转换；业务模块只依赖通用接口和标准结果 |
| C-19 | 厂商 SDK 的安装、许可证、位数、版本和 DLL 加载失败必须可检测并返回明确状态；某个可选引擎不可用时，不得阻止其他引擎或 OpenCV 启动 |
| C-20 | 引擎能力通过 `VisionEngineInfo` / `VisionCapability` 暴露，业务模块执行前检查能力，不依赖引擎名称硬编码 |
| C-21 | `ImageFrame` 仅描述不可变图像视图，`IImageLease` 是唯一可释放的所有权对象；必须明确借用、转移和保留规则，禁止在租约释放后继续使用图像对象 |
| C-22 | VTK 不进入当前二维测距链路；未来三维、点云和体数据能力使用独立扩展边界 |
| C-23 | 实时帧流必须使用有界缓冲区；默认只保留最近 2~3 帧，禁止无界队列堆积完整图像 |
| C-24 | 图像数据使用租约/所有权管理；消费者处理完成前不得归还内存池，处理完成后必须释放租约 |
| C-25 | 高频帧缓冲优先使用 `MemoryPool<byte>`/`ArrayPool<byte>`；禁止每帧无条件 `new byte[]` |
| C-26 | 实时处理允许丢弃过期帧，但必须记录丢帧数量；测距默认采用“最新帧优先”，不等待处理过期帧 |
| C-27 | ROI 操作优先使用视图，不复制整帧；只有格式转换、尺寸变化或跨 SDK 生命周期要求时才创建新缓冲 |
| C-28 | UI 显示频率与算法处理频率解耦；UI 只取最新结果并节流刷新，不逐帧排队渲染 |
| C-29 | 停止、取消、设备断开和异常路径都必须释放帧租约、归还池内存并关闭 SDK 原生对象 |
| C-30 | 采集、处理、UI 三类线程职责分离；处理线程不得阻塞采集线程，UI 不得直接执行视觉算法 |
| C-31 | 所有坐标明确使用图像左上角为原点、X 向右、Y 向下的像素坐标；ROI、检测框和结果不得隐式混用屏幕坐标 |
| C-32 | 帧时间至少区分采集时间、处理开始时间和处理完成时间；实时排序使用单调帧号，不使用本地墙上时间排序 |
| C-33 | 结果必须带明确状态（Valid / NotDetected / NotCalibrated / Unavailable / Failed），不能只用 `null` 判断失败原因 |
| C-34 | 配置必须带版本号和引擎标识；配置加载失败不得静默使用部分旧值，必须返回错误或完整回退默认配置 |
| C-35 | 相机设置必须通过能力模型校验（分辨率、帧率、曝光、增益、焦距/对焦等）；不支持的设置返回 NotSupported，不得假装成功 |
| C-36 | 设备枚举、连接、断开、重连和释放必须幂等；重复 Stop/Close 不得抛出未处理异常 |
| C-37 | 日志和诊断不得依赖具体日志框架；模块通过标准诊断事件/接口输出结构化信息，宿主决定落盘方式 |

### 3.5 约束的落地保障

约束不靠"开发时记得"，每条都对应一种检查手段：**机器强制 > 测试断言 > 人工评审**。

新增 `tests/Visual.Architecture.Tests` 工程（NetArchTest.Rules），在 CI/本地构建时自动执行架构断言。

| 约束 | 保障方式 | 类别 |
| --- | --- | --- |
| C-01 禁引 UI 框架 | ① 类库 csproj 不设 `UseWPF`（物理上无法引用）；② 架构测试断言模块程序集引用列表无 `PresentationFramework` | 机器强制 |
| C-02 仅暴露 Contracts | 架构测试断言：业务模块的 public 类型只允许出现在 `Contracts` 命名空间；实现类必须 `internal`（`InternalsVisibleTo` 仅授予测试工程） | 机器强制 |
| C-03 依赖白名单 | 架构测试断言：业务模块仅引用共享层和视觉能力接口；只有引擎适配器可以引用对应 SDK | 机器强制 |
| C-04 不读写调用方文件 | 模块测试断言：运行前后临时目录外无新增文件；代码评审检查无 `File.*` 直调（IO 统一走抽象） | 测试 + 评审 |
| C-05 异步边界 | 公共业务、IO、设备生命周期和实时流契约使用 `Task`/`ValueTask`/`IAsyncEnumerable` + `CancellationToken`；架构评审禁止 UI/采集线程直接调用同步 CPU 算子 | 机器 + 评审 |
| C-06 异常收敛 | 故障注入测试（坏帧/未标定/设备断开）断言只抛 `VisionException` 系 | 测试断言 |
| C-07 SemVer 版本 | 发布时用 `Microsoft.DotNet.ApiCompat` 对比上一版本公共 API，破坏性变更阻塞发布 | 机器强制 |
| C-08 无 UI 测试工程 | 测试在无桌面环境的 CI 代理上运行，本身即证明 | 机器强制 |
| C-09~C-12 软件层规范 | 代码评审 checklist（见下） | 人工评审 |
| C-13~C-15 范围约束 | 里程碑评审核对 | 人工评审 |
| C-16~C-22 引擎隔离 | 架构测试检查引用关系；适配器测试检查 SDK 缺失/许可证失败；评审检查图像所有权 | 机器 + 测试 + 评审 |
| C-23~C-29 帧生命周期与缓存 | 有界队列测试、租约释放测试、池内存复用测试、丢帧指标和压力测试 | 测试断言 |
| C-30~C-37 运行时一致性 | 线程、坐标、时间、状态、配置、设备能力、幂等释放和诊断测试 | 测试 + 评审 |

**§4.6 判定标准的使用方式**：新功能立项/PR 评审时逐条打勾（4 条问题），全勾 → 归基础能力；任一不勾 → 归业务模块。勾选结果写进 PR 描述，不需要每次重读全文。

## 4. 解决方案结构

```text

├─ src/
│  ├─ shared/                        # ===== 引擎无关的共享层 =====

│  │  ├─ Visual.IO/                  # IFrameSource 等帧源契约

│  ├─ engines/                       # ===== 具体视觉引擎适配器 =====

│  │  └─ Visual.Engine.VisionPro/    # VisionPro 适配器预留，需独立 SDK/许可证
│  ├─ modules/                       # ===== 业务模块层（对外交付的 DLL）=====
│  │  └─ Visual.Distance/            # ★ 测距模块（本期唯一业务模块）
│  │     ├─ Contracts/               # 对外：IDistanceService、DistanceMeasurement、
│  │     │                            #      CalibrationInfo、NotCalibratedException
│  │     └─ Internal/                # 对内：单目标定换算、测距服务实现
│  │                                 #      （组合 VisionBase 与引擎能力，不依赖具体 SDK）
│  ├─ app/                           # ===== 软件层（不可拆、不对外）=====
│  │  ├─ Visual.App/                 # WPF 可执行程序（View/ViewModel/启动）
│  │  └─ Visual.AppCore/             # 软件内部：ROI 鼠标交互、叠加渲染、菜单挂载、

│  ├─ Visual.Engine.OpenCv.Tests/    # OpenCV 适配器样图测试
│  └─ Visual.Distance.Tests/         # 测距业务测试，不依赖具体引擎
└─ samples/
   └─ Visual.Distance.ConsoleDemo/   # 无 UI 调用示例（验证可拆性）
```

### 4.1 依赖方向（单向、不可违反）

```
Visual.App / AppCore ──► Visual.Distance
        │                       │
        │                       ├──► Visual.IO / Visual.Vision.Contracts
        │                       └──► Visual.VisionBase
        │
        └──► Visual.Engine.OpenCv

Visual.VisionBase ─────► Visual.IO / Visual.Vision.Contracts / Visual.Image / Visual.Abstractions
Visual.Engine.* ───────► Visual.IO / Visual.Vision.Contracts / Visual.Image / Visual.Abstractions
Visual.IO / Visual.Vision.Contracts ──► Visual.Image / Visual.Abstractions
Visual.Image ──────────► Visual.Abstractions
```

- 业务模块不得直接引用任何具体引擎；
- 引擎适配器不得被业务规则反向依赖；
- 引擎原生对象只能存在于对应适配器内部；
- VTK 不进入当前二维测距链路，未来单独建立三维/点云扩展。

### 4.2 分层约束矩阵

以下矩阵是分层的主要判断依据。新增类、接口或工程时，先判断它属于哪一层，再检查依赖方向。

| 层级 | 代表工程 | 主要职责 | 允许依赖 | 禁止依赖/行为 | 对外内容 |
| --- | --- | --- | --- | --- | --- |
| L1 基础契约 | `Visual.Abstractions` | 坐标、尺寸、帧元数据、结果状态、错误码、模块入口 | .NET BCL | 禁止视觉 SDK、WPF、文件 IO、线程调度、算法 | public 值对象和基础接口 |
| L2 图像资源 | `Visual.Image` | 图像格式、帧数据、池内存、租约、ROI 视图、有界缓冲 | L1、.NET BCL | 禁止 OpenCV/HALCON/VisionPro 类型；不做检测和业务判断 | `ImageFrame`、`ImageView`、租约和缓冲接口 |
| L3 能力契约 | `Visual.IO`、`Visual.Vision.Contracts` | 定义帧源、检测、跟踪、预处理、引擎和设备能力接口 | L1、L2 | 禁止具体 SDK 实现；不保存业务状态 | 能力接口、事件参数、能力描述 |
| L4 公共流程 | `Visual.VisionBase` | ROI 校验、几何计算、流程组合、结果构造、引擎能力选择、诊断抽象 | L1~L3 | 不直接调用具体 SDK；不输出距离/OK-NG 等业务结论 | 无状态公共服务和流程类 |
| L5 引擎适配 | `Visual.Engine.OpenCv` 等 | 适配 SDK、图像转换、设备访问、算子和检测实现、原生异常转换 | L1~L4、对应 SDK | 不包含测距业务规则；不得让原生类型穿透到上层 | `IVisionEngine`、`IFrameSource`、设备和能力实现 |
| L6 业务模块 | `Visual.Distance` | 标定、检测结果组合、距离换算、业务状态和标准距离结果 | L1~L4；运行时能力对象由宿主注入 | 禁止引用 L5 工程、具体 SDK、WPF、设备驱动和文件系统 | `IDistanceService`、DTO、模块异常和构建入口 |
| L7 应用宿主 | `Visual.AppCore`、`Visual.App` | UI、配置持久化、模块/引擎选择、线程编排、显示和用户提示 | 全部 public 契约、具体模块和已选适配器 | UI 不写算法；不把 WPF 类型传入业务模块；不绕过模块调用 SDK | View、ViewModel、应用服务 |

#### 分层判断规则

1. 只描述数据和契约，放 L1~L3；
2. 对图像做通用组合但没有业务结论，放 L4；
3. 调用某个视觉 SDK 或设备 SDK，放 L5；
4. 持有标定、阈值、配方并输出距离、判定等业务结果，放 L6；
5. 依赖 WPF、配置文件、用户交互或宿主生命周期，放 L7；
6. 一个类同时满足两个层级时，优先拆分，不允许用“方便调用”跨层放置。

### 4.3 各层职责一句话

| 层 | DLL | 职责 | 独立交付？ |
| --- | --- | --- | --- |
| 基础契约 | Visual.Abstractions | 跨模块通用的值对象/结果基类/异常/模块入口形态 | 是（随模块一起走） |
| 图像抽象 | Visual.Image | 图像格式、帧信息、内存所有权与生命周期 | 是（随模块一起走） |
| IO 契约 | Visual.IO | 只定义帧源生命周期与帧事件，不绑定采集 SDK | 是（随模块一起走） |
| 视觉契约 | Visual.Vision.Contracts | 定义检测、跟踪、算子、引擎能力的通用接口 | 是（随模块一起走） |
| 视觉基础 | Visual.VisionBase | 引擎无关的几何、结果整理和公共流程工具 | 是（随模块一起走） |
| 引擎适配 | Visual.Engine.* | 将 OpenCV/HALCON/VisionPro 转换为公共接口 | 按引擎独立部署 |
| 业务模块 | Visual.Distance | 组合公共零件完成一个完整业务功能 | **是（核心交付物）** |
| 软件层 | Visual.App / AppCore | 人机交互与模块编排 | 否（WPF 耦合） |

### 4.4 为什么这样细分（拆 DLL 的判断标准）

**拆 DLL 的唯一理由：存在"独立的消费边界"——即有调用方只想用这一层、且可能单独升级它。**

- **Abstractions 必须拆**：它是所有模块和宿主之间的"语言"，调用方只引用它就能定义自己的适配层；版本变化最慢。
- **Image/IO/Vision Contracts 必须拆**：它们定义跨引擎边界，避免业务模块绑定具体 SDK。
- **VisionBase 必须拆**：它是未来所有业务模块的公共件；不拆则每个新模块复制一份通用流程。
- **引擎适配器必须拆**：厂商 SDK、许可证和部署条件不同，必须能够单独加载或缺失。
- **Distance 必须拆**：本期核心诉求本身。

### 4.5 明确不再细分的部分（及原因）

| 候选拆分 | 结论 | 原因 |
| --- | --- | --- |
| 标定（Calibration）独立成 DLL | **不拆**，留在 Distance 模块内 | 单目标定公式与测距强耦合（同一组参数、同一次换算），当前无第二个消费者；独立出来只会多一次跨 DLL 传参。未来出现"多模块共用标定"再拆，届时从 Distance.Internal 平移即可 |
| 预处理 / 检测 / 跟踪 / 分析算子各自成 DLL | **不拆**，合并为 VisionBase 或具体引擎适配器内部 | 通用流程和具体 SDK 实现不是同一层；先按接口隔离，不按每个算子拆程序集 |
| 摄像头源 / 文件源各自成 DLL | **不拆**，统一实现 `IFrameSource` | 差异只是帧来源；具体 SDK 实现放引擎适配器，避免 IO 工程绑定 OpenCV |
| HALCON / VisionPro 各自独立适配器 | **必须拆** | SDK、许可证、部署和能力不同，不能合并成一个引擎工程 |
| 每个模块的 Contracts 单独成 DLL | **不拆**，Contracts 作为模块 DLL 内的文件夹 | 模块契约与模块同生命周期、同版本；单独成 DLL 会产生大量"1 个接口 1 个 DLL"的碎片，引用方反而要管理双倍依赖 |
| AppCore 的叠加渲染拆 DLL | **不拆** | 叠加渲染依赖 WPF 的 DrawingVisual/WriteableBitmap，离开 WPF 无意义，违反 C-01 |
| 按"实体/值对象/接口"分 DLL | **不拆** | 按代码种类分包没有消费边界支撑，只会得到互相依赖的 DLL 网 |

**原则总结：DLL 边界 = 消费边界 + 独立版本化需求；层内细分用命名空间/文件夹解决，不滥用程序集。**

### 4.6 基础 vs 业务的判定标准

拿到任何一项视觉能力，按下面四条判定。**四条全满足 → 归基础能力（接口/流程归 `Vision.Contracts` 或 `VisionBase`，具体实现归引擎适配器）；任一不满足 → 归业务模块。**

| # | 判定问题 | 基础能力（Contracts / VisionBase / 引擎适配器） | 业务（模块） |
| --- | --- | --- | --- |
| 1 | 输出含**业务结论**吗？（带单位/判定的结果：距离 mm、OK/NG、数量报表） | 不含，只输出图像/几何数据（掩膜、轮廓、坐标、相似度） | 含 |
| 2 | 持有**业务状态**吗？（标定参数、业务阈值、配方、会话） | 无状态，纯函数式"帧进→数据出" | 有状态 |
| 3 | 知道"**目标是什么**"吗？（类别语义、业务对象） | 不知道，只认像素与几何特征 | 知道（"这是零件 A"） |
| 4 | 换一个业务场景，**原样还有用**吗？ | 有用（任何场景都要灰度/找轮廓） | 没用，需要改参数语义或流程 |

一句话版：**"换个业务场景它还能原样复用吗？能 → 基础；不能/输出业务结论 → 业务。"**

#### 判定示例（争议项对照）

| 能力 | 归类 | 理由 |
| --- | --- | --- |
| 灰度、二值化、滤波、形态学、边缘 | 基础 | 纯像素变换，无业务语义（判定 1/4） |
| Blob/轮廓分析、模板匹配 | 基础 | 输出几何数据，不知道目标是什么（判定 3） |
| 缺陷类算子（污点/划痕/差异对比） | 基础 | 只输出"疑似异常区域+面积"，**不下 OK/NG 结论**（判定 1）；OK/NG 判定属业务 |
| "在 ROI 内找最显著目标并跟踪"（ITracker/TargetDetectorBase） | 基础 | 通用手段，测距和未来的计数等场景都能用（判定 4） |
| 标定 + 距离换算 | 业务 | 持有标定状态（判定 2），输出带单位的业务结论 mm（判定 1） |
| "识别目标是哪种零件/图形" | 业务 | 含类别语义，依赖具体对象库（判定 3） |
| "目标越界/停留超时"判断 | 业务 | 含业务规则与阈值（判定 1/2） |

#### 推论

- "计算之前的一切"（采集、预处理、找目标、跟踪）默认归基础层——它们不带业务结论；
- "识别"要拆开看：**找目标**（detection，几何层面）是基础；**认出是什么**（classification，语义层面）是业务；
- 一个业务模块 = 基础能力的组合 + 业务状态 + 业务结论。Distance 即是如此：通过 `Vision.Contracts` 调用宿主注入的检测能力 → 模块内标定状态 → 输出 mm。

后续新业务功能 = `modules/` 下新增 `Visual.<功能>/`（依赖共享契约和视觉能力接口）+ App 内挂菜单，结构不变。

> 本章为结构概述与划分原则；各项目的类级设计（类名、方法、作用）见 [02-结构与类设计](./02-结构与类设计.md)。

## 7. 输出（Outputs）

### 7.1 模块 DLL 输出（API 级）

`MeasureAsync` 返回 `IReadOnlyList<DistanceMeasurement>`（每个传入 ROI 一条），单条结构：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| TargetId | string | 目标标识（与传入 ROI 对应） |
| SourceId | string? | 帧源标识（多相机预留，单源时为 null） |
| FrameIndex | long | 单调递增帧号，用于实时排序和关联诊断 |
| Status | VisionResultStatus | Valid / NotDetected / NotCalibrated / Unavailable / Failed |
| ErrorCode | VisionErrorCode? | 失败或不可用时的结构化错误码；成功时为 null |
| Distance | double? | 距离值；未检出/未标定为 null |
| Unit | DistanceUnit | Mm / Cm / M |
| Confidence | double | 0~1 |
| TargetCenter | Point2D? | 目标中心（像素） |
| TargetPixelSize | double? | 目标像素尺寸 |
| Timing | FrameTiming | 采集、处理开始、处理完成时间及处理耗时 |

实时模式：事件/流式推送同一集合结构。

### 7.2 软件输出（用户级）

- 实时画面叠加：目标框（绿）/未检出（灰）、距离文本（值+单位）
- 状态栏：未启动 / 未标定 / 未检出 / 测量中（当前距离）
- 标定参数本地持久化（JSON）

### 7.3 分发输出

按引擎和调用方式分发（每组含版本号、依赖说明和最小示例）：

| 分发包 | 包含 DLL | 适用调用方 |
| --- | --- | --- |
| OpenCV 测距包 | Abstractions + Image + IO + Vision.Contracts + VisionBase + Distance + OpenCV 适配器 + OpenCV runtime | 使用 OpenCV 运行时的外部项目 |
| 外部帧测距包 | Abstractions + Image + IO + Vision.Contracts + VisionBase + Distance + 对应检测能力适配器 | 已有相机/帧源、但需要视觉检测能力的宿主 |

## 9. 验收标准（Acceptance Criteria）

### 9.1 验收场景

| 场景 | 前置条件 | 步骤 | 预期结果 |
| --- | --- | --- | --- |
| S1 软件闭环 | 接好摄像头 | 打开软件 → 圈选 ROI → 标定 → 观察 | 实时显示距离，移出目标显示未检出 |
| S2 测距精度 | 已标定 | 目标置于 3 个已知距离点（近/中/远），各测 10 次 | 平均误差 ≤ ±10%，单位正确 |
| S3 标定持久化 | 完成标定 | 重启软件 | 标定参数自动加载，无需重标 |
| **S4 DLL 独立可用** | 拿到完整测距包 DLL 组 | 新建控制台项目仅添加 DLL 引用，按最小调用序列跑视频文件 | 编译通过，逐帧输出距离，全程无 WPF/无软件安装 |
| S5 宿主集成 | HardwareModularWorkflow 提供 `ImageFrame` 或接入 OpenCV 适配器 | 在其相机驱动中调用 `MeasureAsync`，工作流编排执行 | 距离作为步骤结果返回（`CommandResult.Data`），宿主不依赖具体引擎类型 |
| S6 异常鲁棒 | — | 未标定测距 / 坏视频文件 / 采集中拔摄像头 | 自定义异常或明确状态提示，进程不崩溃 |
| S7 性能 | 720p 视频 | 连续 10 分钟 | ≥ 15 次/秒，UI 无卡顿 |
| S8 稳定性 | — | 连续运行 2 小时 | 无崩溃，内存增长 < 10% |

### 9.2 验收口径

- AC-M1：S1~S8 全部通过；
- AC-M2：**S4（DLL 独立可用）与 S5（宿主集成）是本项目的核心验收项**，证明"功能可拆分给别处直接使用"；
- AC-M3：精度满足 NFR-02（±10%）。

### 9.3 验收交付物

- Visual.App 可运行软件；
- 分发 DLL 组（按 §7.3）+ 依赖清单 + 最小调用示例；
- ConsoleDemo 与模块测试工程源码；
- 验收测试记录表（S1~S8 签认）。
