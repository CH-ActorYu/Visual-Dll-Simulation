## 1. 设计目标

- 业务模块不暴露 OpenCV、HALCON、VisionPro 或 WPF 类型；
- 单帧与实时流使用同一结果 DTO；
- `TargetId` 从输入到输出稳定映射；
- 帧所有权只有一个明确入口，不重复释放、不泄漏；
- 实时处理有界、最新帧优先、可取消；
- 停止、异常和设备断开均能确定性释放资源。

## 2. 核心 DTO

以下为契约形态，编码时允许按 C# 语法微调，但不得改变语义。

```csharp
public sealed record TargetRegion(
    string TargetId,
    RoiRect Bounds);

public sealed record DistanceRequest(
    ImageFrame Frame,
    IReadOnlyList<TargetRegion> Targets);

public sealed record CalibrationInfo(
    double TargetPhysicalWidth,
    double ReferencePixelWidth,
    double ReferenceDistance,
    DistanceUnit Unit,
    PixelMeasureAxis MeasureAxis,
    string CameraId,
    ImageSize ImageSize,
    string DetectionProfileId,
    DistanceRange ValidDistanceRange,
    bool DistortionCorrected,
    int SchemaVersion);
```

`PixelMeasureAxis` 和 `DetectionProfile` 定义在 `Visual.Vision.Contracts`，使 Distance 与所有引擎适配器依赖同一配置契约，禁止把它们定义在具体引擎或业务模块中。

约束：

- `Targets` 不得为 null 或空集合；
- `TargetId` 非空且在一次请求中唯一；
- 结果数量、顺序和 TargetId 与输入一致；
- 同一服务实例的多目标共享一份活动标定和 DetectionProfile，本期只支持真实测量宽度相同的目标；
- 配置、标定和检测 Profile 在一帧处理期间不可变；
- 热路径不解析 JSON，JSON 只用于配置导入、导出和持久化边界。

## 3. IDistanceService

```csharp
public interface IDistanceService : IVisionModule, IAsyncDisposable
{
    bool IsCalibrated { get; }

    void SetCalibration(CalibrationInfo calibration);

    ValueTask<IReadOnlyList<DistanceMeasurement>> MeasureAsync(
        DistanceRequest request,
        CancellationToken cancellationToken = default);

    IAsyncEnumerable<IReadOnlyList<DistanceMeasurement>> MeasureStreamAsync(
        IFrameSource source,
        IReadOnlyList<TargetRegion> targets,
        CancellationToken cancellationToken = default);
}
```

服务拥有由引擎创建的 ROI 跟踪器，调用方必须释放 `IDistanceService`。服务可以在实时枚举开始时打开/启动尚未运行的帧源，并在枚举结束、取消或订阅者提前退出时停止/关闭它；服务不调用帧源的 `DisposeAsync`，帧源对象所有权仍归调用方。调用方传入已运行帧源时，服务不负责停止它。

`DistanceServiceBuilder` 通过 `WithDetectionProfile(...)` 接收 Profile。显式 `WithDetector(...)` 的实现优先；没有显式 Detector 时由 `WithEngine(...)` 根据 Profile 创建；两者均不存在、引擎不可用或缺少 Detection 能力时 `Build()` 立即失败，不延迟到第一帧才报错。

### 3.1 单帧错误语义

- 未标定：抛 `NotCalibratedException`；
- 参数非法、TargetId 重复、帧无效：抛 `VisionException(InvalidInput)`；
- 取消：传播 `OperationCanceledException`；
- 第三方 SDK 异常：转换为 `VisionException`；
- ROI 合法但没有目标：正常返回 `Status=NotDetected`，不抛异常。

### 3.2 实时流错误语义

- 单帧未检出、未标定或暂时不可用：输出对应状态，流继续；
- 设备短暂断开：输出诊断并按设备策略重连；
- 无法恢复的设备、引擎或配置错误：流以 `VisionException` 结束；
- 取消属于正常结束路径，必须释放全部资源；
- 订阅者停止枚举等同于取消当前流。
- `targets` 在一次流生命周期内视为不可变；UI 修改 ROI 时取消旧流并以新快照启动新流。

## 4. 同步与异步边界

公共业务、IO、设备生命周期和实时流 API 必须异步并接受 `CancellationToken`。

单帧 CPU 算子允许保持同步：

```csharp
TargetCandidate? Detect(ImageFrame frame, RoiRect roi);
IImageLease Apply(ImageFrame source);
```

理由是这些算子本身不执行 IO，强行包装 `Task.Run` 会增加高频帧开销。预处理输入帧只借用，输出必须以租约交接并由调用方释放，不能返回无法表达所有权的裸新帧。它们只能由 `VisionRuntime` 的处理线程调用，UI 和采集线程不得直接调用。公共 `MeasureAsync` 负责提供异步边界和取消检查。

## 5. 图像与租约模型

采用单一所有权原则：

- `ImageFrame` 使用 `ReadOnlyMemory<byte>` 暴露不可变图像视图，不负责归还池内存；
- `IImageLease` 是唯一可释放的所有权对象；
- `ImageView` 只是租约有效期内的 ROI 视图；
- SDK 包装对象不得超过其依赖租约的生命周期。

```csharp
public interface IImageLease : IDisposable
{
    ImageFrame Frame { get; }
    bool IsReleased { get; }
    IImageLease Retain();
}
```

`Retain()` 只用于确实存在多个异步消费者的情况。每次 `Retain()` 必须有一次对应的 `Dispose()`。

## 6. 单帧交接规则

`MeasureAsync` 借用 `DistanceRequest.Frame`：

1. 调用方持有帧租约；
2. 调用方保证租约在返回的 `ValueTask` 完成前有效；
3. Distance 不释放调用方租约；
4. Distance 返回后不得保存帧、ImageView、Mat 或其他原生图像对象；
5. 需要跨调用保存的数据必须复制到模块自有内存；
6. 结果 DTO 不得引用帧内存。

```csharp
using IImageLease lease = frameFactory.Rent(...);

var request = new DistanceRequest(lease.Frame, targets);
var results = await service.MeasureAsync(request, cancellationToken);
```

## 7. 实时帧源

推荐帧源接口：

```csharp
public interface IFrameSource : IAsyncDisposable
{
    string SourceId { get; }
    FrameSourceState State { get; }
    long DroppedCount { get; }

    ValueTask OpenAsync(CancellationToken cancellationToken = default);
    ValueTask StartAsync(CancellationToken cancellationToken = default);
    IAsyncEnumerable<IImageLease> ReadFramesAsync(
        CancellationToken cancellationToken = default);
    ValueTask StopAsync(CancellationToken cancellationToken = default);
    ValueTask CloseAsync(CancellationToken cancellationToken = default);
}
```

实现内部使用容量 2~3 的有界 `FrameBuffer`。采集线程只写缓冲，不等待视觉处理完成。

## 8. FrameBuffer 所有权

`TryWrite(IImageLease lease)` 的规则：

- 返回 true：所有权转移给 FrameBuffer，调用方不得再释放或使用该租约；
- 返回 false：所有权仍属于调用方，调用方负责释放；
- 缓冲满时释放最旧的未消费租约并递增 `DroppedCount`；
- `TryReadLatest()` 返回最新租约的所有权，并释放所有更旧的未消费租约；
- `Complete()` 释放队列中全部租约；
- 重复 `Complete()` 必须幂等。

实时处理循环：

```text
采集租约
  → FrameBuffer 接管
  → 消费者取得最新租约
  → using/finally 保证释放
  → ROI ImageView
  → 临时 SDK 包装
  → 检测/测距
  → 纯 DTO 结果
  → 释放 SDK 包装
  → 释放租约
```

`VisionRuntime` 是实时消费端的租约终点：`ReadFramesAsync` 交出的租约由运行时接管，并在单帧处理成功、算法异常或取消时通过 `using/finally` 释放。`IFrameProcessor` 在 `ProcessAsync` 调用期间只借用 `ImageFrame`，不得保存帧或自行释放其来源租约。预处理流水线内部产生的中间租约由流水线释放，返回的最终租约再由调用方负责释放。

`IVisionEngine.CreateTracker` 返回的 `ITracker` 由调用方拥有并必须释放。跟踪器可以保存跨帧模板或原生状态，但不得保存输入 `ImageFrame`；重新初始化和 `Dispose` 都必须释放旧的跟踪状态。

## 9. 引擎适配器规则

- 包装外部内存时，Mat/HObject/CogImage 的寿命不得超过源租约；
- SDK 必须拥有内存时创建独立租约并复制；
- 每次整帧复制必须记录原因和计数；
- 原生异常转换后仍要在 `finally` 中释放原生对象；
- 引擎适配器不得缓存调用方帧；
- 引擎不可用时返回结构化状态，不把 SDK 异常类型暴露给上层。

## 10. UI 交接

- UI 不持有采集租约；
- UI 只消费 `DistanceMeasurement`、诊断快照或专用显示副本；
- 显示副本与处理帧解耦，并按配置频率节流刷新；
- UI 处理慢不能反向阻塞采集和算法线程；
- 切换页面或关闭窗口时取消结果枚举，不直接释放业务模块内部对象。

## 11. 停止与异常清理顺序

```text
发出取消
  → 停止接受新帧
  → 停止/关闭设备采集
  → Complete FrameBuffer
  → 等待当前处理退出
  → 释放当前帧和转换缓冲
  → 释放 SDK 原生对象
  → 完成结果流
```

`StopAsync`、`CloseAsync`、`Complete` 和 `DisposeAsync` 必须幂等。取消、设备断开和异常路径必须执行同一清理逻辑。

## 12. 配置一致性

- `SetCalibration` 只更新标定；
- `Configure(ModuleConfiguration)` 原子替换完整模块配置；
- ModuleConfiguration 携带 schema、引擎标识和 JSON payload；模块在 Configure 边界一次性反序列化、校验并生成强类型快照，不在每帧处理时解析；
- `Configure` 成功后生成新的不可变配置快照；
- 配置失败时保留原配置，不允许部分字段生效；
- `SetCalibration` 成功后更新当前配置中的完整标定快照；
- 相机、分辨率、检测 Profile 或 schema 不兼容时将 `IsCalibrated` 置为 false。

## 13. 必须保持的生命周期不变量

1. 每个租约最终释放且只释放一次；
2. 已释放租约的帧不得再次访问；
3. 队列长度永不超过配置上限；
4. 取消后队列和当前处理不残留租约；
5. 结果 DTO 不引用图像内存；
6. 模块不保存调用完成后的帧；
7. UI 不阻塞采集线程；
8. 第三方原生对象不穿透适配器边界。
